## 2026-11-09：调整第一版设计

| 决定 | 原因 |
| :--- | :--- |
| 不再定位为通用二进制框架 | 第二种格式本来就是最先砍掉的功能，实际只有 WAD；Schema 能力已有 EByte、RaE 等项目 |

## 2026-11-09：wad-roundtrip 补写 Spec 后的七项决定

| 决定 | 原因 |
| :--- | :--- |
| D-5：`WadFile.parse` 复制输入，内部缓冲不暴露，`original()` 返回副本，删除 `baseBuffer`（已实现） | 原来 `parse` 保留调用方传入的同一个数组，调用方修改它就会改变 `serialize()` 的结果，“无改动时与输入逐字节相同”失去保证，而且没有任何提示。TypeScript 没有只读的 `Uint8Array`，不暴露引用才可靠。不提供跳过复制的选项，避免引入需要信任调用方的前提 |
| X-1：`setField` 的目标字段区间与文件头、目录或其他 Lump 的数据区间重叠时拒绝，解析仍不拒绝（已实现） | 目录项 `filepos` 为 0 的 WAD 能解析，但 `setField` 会改写文件头，重新解析抛 `BAD_IDENT`，I-2 不成立。解析阶段保持宽容，才能让非常规历史数据无损往返；写入是新操作，可以严格 |
| D-6：`ByteOverlay` 移出 `@necrohex/core` 公开入口，只经内部子路径提供（已实现，约定级隔离） | `ByteOverlay.write` 接收裸偏移和字节，公开导出会让上层包绕过 `setField` 的全部校验。它是补丁引擎要用的积木，不能删除。子路径和相对路径导入仍能绕过，所以靠测试断言公开入口不导出它来发现误用，不声称技术隔离 |
| X-3 与 D-9：地图作用域包含 `BEHAVIOR`、`SCRIPTS` 并识别 UDMF，`MapScope.format` 区分 Doom、Hexen、UDMF，非 Doom 地图的记录访问一律拒绝；只识别，不解析（已实现） | Hexen 的 `THINGS` 是 20 字节一条，按 10 字节的 Doom 布局读写会落在错误偏移且不报错，违反“不猜测”。作用域漏掉扩展 Lump 会让将来的 PWAD 导出缺 Lump。识别靠名称启发式，不能覆盖所有来源的 WAD |
| D-1：`PLAYPAL` 不属于 `wad-roundtrip`（后续可选） | 未解析的 Lump 本来就原样保留，字节保真不受影响。生成器没有一字节类型，大 `count` 字段会生成逐元素元组，需要先改生成器 |
| D-8：使用 GitHub Actions，整包测试下载固定版本的 Freedoom 并校验 SHA-256 后缓存，`REQUIRE_FREEDOOM=1` 时缺文件失败而不是跳过（延后到 `wad-export` 完成之后，目前没有 CI 配置） | 缺 cache 时整包用例被 `skipIf` 跳过，测试仍显示通过，整包 I-1 可能在 CI 里从未运行。固定版本和校验和让结果可重复 |
| 决定 7（X-4）：不属于任何地图作用域的记录 Lump 可读不可写，读取接口行为不变，`setField` 抛 `OUTSIDE_MAP_SCOPE`（已实现） | 读取没有副作用，按 Doom 布局读错最多得到一份无意义的预览；写入必须能证明目标属于一张已识别的 Doom 地图，记录大小和字段偏移才有依据。作用域识别是名称启发式，误判的方向是拒绝写入，而不是错误写入 |

## 2026-11-09：wad-export 的实现选择

| 决定 | 原因 |
| :--- | :--- |
| 完整 WAD 导出就是 `serialize()` 的结果，`exportFullWad` 同时返回改动区间 | 文件长度、目录和未改动的字节都与源文件相同，字节局部性可以直接比较 |
| PWAD 默认导出所有含修改的地图，每张地图写入标记和作用域内的全部数据 Lump（含 `BEHAVIOR`、`SCRIPTS` 等扩展成员），原始名称字节和数据逐字节复制 | 只放改动的 Lump，引擎会因缺少 `LINEDEFS` 等 Lump 拒绝载入地图，冒烟测试的对照用例复现了这一点 |
| 修改落在导出的 Lump 之外、地图名找不到或重名、导出地图的 Lump 数据不在文件内时，`exportPwad` 拒绝并不产生输出 | 这几种情况分别会静默丢掉修改、猜测目标或写出空 Lump |
| 导出后立即重新解析 PWAD，核对 Lump 名称字节、数据和地图作用域 | 报告里能写明“检查过什么”，作用域识别是名称启发式，导出结果要用同一套规则复核 |
| 冒烟引擎用 DSDA-Doom 0.30.1（GPL-2.0），安装在仓库之外，测试通过 `NECROHEX_ENGINE` 环境变量找到它；缺引擎或缺 `fixtures/cache/freedoom2.wad` 时跳过 | 它有 `-timedemo`、`-nodraw`、`-nosound`、`-no_message_box`，无窗口运行；录像跑完打印 `Timed N gametics` 并以 0 退出，地图缺 Lump 时以非零状态退出。GPL 引擎不能进 MIT 仓库 |
| “运行若干 tic”用生成的无输入 v1.9 演示录像实现，按 `-timedemo` 回放 | 录像头指定地图和难度，tic 数由录像长度决定，不依赖引擎的控制台或脚本功能 |
| 冒烟测试只报告通过的检查：引擎载入了这个 PWAD、在目标地图上跑完指定 tic 数、正常退出 | 跑完若干 tic 不能证明地图可以通关 |
| 启动子进程的代码放在 `@necrohex/adapter-wad/node` 子路径，主入口不导入 Node 模块 | 工作台在浏览器里使用 `adapter-wad` 的主入口 |

## 2026-11-09：写入护栏的实现选择

需要决定的地方都先取最保守的做法，之后可以放宽。

| 决定 | 原因 |
| :--- | :--- |
| 结构检查放在 WAD 记录源里（`writeField` 和写入后的 `checkWrites`），拒绝为 `VALUE_REJECTED`，不能 opt-in；可玩性检查是保护钩子，拦截类可以在 `allowProtected` 中逐个放行 | 结构错误会写出无效的地图，不应由补丁作者放行；可玩性规则有合理的例外 |
| 只检查新值：写入字节与当前字节相同的贴图名和 Thing 类型不检查；`ceilingheight >= floorheight` 只在高度字段实际改变时检查，并按全部写入完成后的值判断 | 解析时不能拒绝历史数据。按写入后的值判断，同一补丁同时抬高地板和天花板才不会因写入顺序被误拒 |
| 贴图名在当前 WAD 的 `F_START`/`F_END`（或 `FF_START`/`FF_END`）之间和 `createWadAdapter({ baseIwad })` 给出的基础 IWAD 中查找，不分大小写；两处都没有就拒绝 | PWAD 通常不带 Flat，不给基础 IWAD 时无从确认，按“不猜测”拒绝。原版引擎查找 Flat 名时也不分大小写 |
| Thing 类型表只收原版 Doom / Doom II 的类型。新类型不在表里为结构拒绝；旧类型不在表里时 `thing-category` 无法判断类别，默认拒绝 | Boom、MBF、ZDoom 的扩展类型需要另行确认语义 |
| 玩家出生点、传送目标、钥匙和 Boss 类型：对这些 Thing 的任何字段写入都拒绝，不只是 `type`；把别的 Thing 改成这些类型也拒绝。出生点、传送目标、钥匙、Boss 各用一个钩子名 | 移动坐标或改难度标志同样会让关卡无法完成。反向也拦截，否则再应用补丁时第一次写入的值会变成受保护的旧值。分开命名让 opt-in 只放行需要的那一类 |
| 地图依赖的 Boss 按原版规则和地图名判断：MAP07 的 67、68，E1M8 的 3003，E2M8 和 E4M6 的 16，E3M8 和 E4M8 的 7；72、87、88、89 在所有地图上都受保护。不读取 UMAPINFO | 原版引擎只按地图名和类型触发这些动作；扩展地图信息另行处理 |
| 类别区分立地障碍物、悬挂障碍物、不阻挡的装饰和爆炸桶 | 把不阻挡的装饰换成障碍物可能堵住通道；悬挂物生成在天花板上；爆炸桶可以被打掉 |
| 尺寸变大的警告覆盖所有阻挡类别（怪物、爆炸桶、障碍物），不只是怪物 | 卡住通道的风险相同，警告不阻止写入 |
| 改高度的警告：扇区 `tag` 非零（不论是否有线段使用这个 tag），或位于 tag 为 0 的特效线段背面（原版手动门） | 不模拟 Boom 广义线段和脚本，宁可多警告 |
| `planPatch` 和 `applyPatch` 的结果加 `checks`，逐项给出 passed、failed、warned、allowed 或 incomplete。有条目在结构检查之前就被排除时为 incomplete，不写 passed。说明文字不出现“可玩”或“保证” | 报告只能说明做过哪些检查 |
| 新增 `createWadAdapter`，`wadAdapter` 是不带基础 IWAD 的实例；每个实例各自登记写回通道 | 基础 IWAD 是打开 adapter 时的配置，不应该进入补丁或 core 的选项 |

| 决定 | 原因 |
| :--- | :--- |
| `Linedef.sidenum` 和 `Sidedef.sector` 从 `int16` 改为 `uint16`，0xFFFF 表示“无”，代码里用 `NO_INDEX` 常量比较。`Linedef.v1`、`v2` 原本就是 `uint16`。其余字段都不是指向记录的下标（`Linedef.tag`、`Sector.tag` 是 tag 编号，按 `int16` 不变） | 按 `int16` 读，单面线段的背面读成 -1，32768 以上的下标读成负数，重定位要用这些字段找扇区的边界线段。只改读法，文件字节不变，I-1 不受影响。`Linedef`、`Sidedef` 不可写，所以写入范围的变化没有对外影响 |

## 2026-11-09：pin 重定位的实现选择

按设计文档第 7 节实现，没有单独写 Spec。

| 决定 | 原因 |
| :--- | :--- |
| core 只按相似度分级（`packages/core/src/patch/relocate.ts`）；指纹的形状、计算和相似度由 adapter 通过 `RecordSource.fingerprints` 提供 | core 不认识 WAD。分级规则（阈值、歧义、缺失）与格式无关，放在 core 里才能对所有 adapter 一致 |
| 只有 `Sector` 支持指纹。指纹恰好六个键：`tag`、`floorpic`、`ceilingpic`、`heights`、`centroid`、`lineCount`；缺键、多键、类型不对，或给 `Thing` 写指纹，都是 `INVALID_PATCH`，不忽略 | 设计文档只定义了扇区指纹。静默忽略写错的指纹会让作者以为做过校验 |
| 边界线段是任一面 Sidedef 指向该扇区的 Linedef；几何中心是这些线段端点按坐标去重后的平均，四舍五入到整数；没有边界线段时 `centroid` 为 `null`。越界的 Sidedef、扇区、顶点引用跳过，不报错 | 按坐标去重，版本之间顶点重新编号不影响结果。解析不拒绝历史数据 |
| 相似度为加权和：几何中心 0.4（相距 32 个单位及以上得 0，线性衰减）、高度 0.2（地板、天花板各一半）、线段数 0.1（按相对差）、`floorpic`、`ceilingpic`、`tag` 各 0.1。取 4 位小数后再比较 | 只有几何中心能区分属性相同、位置不同的扇区，所以权重最大；属性相同、位置不同的扇区最多 0.6，到不了 0.85 |
| 分级：相似度 ≥ 0.5 为候选，≥ 0.85 为高置信度。只有一个高置信度候选，并且第二名候选低于 0.85、比它至少低 0.1 时才应用（下标相同为 `EXACT`，不同为 `RELOCATED`）；有候选但不满足这一条为 `CONFLICT_AMBIGUOUS`，包括只有低于 0.85 的候选；没有候选为 `CONFLICT_MISSING`。并列第一一定是歧义 | 设计文档要求“只有一个候选达到高置信度”。只看 0.85 时，真实数据里 0.85 对 0.8 这样相近的候选会被选中并且选错（见下面的校准）；只有低于 0.85 的候选时，它是“相近但不够确定”，按不猜测拒绝 |
| `expectedIndex` 越界时仍然重定位 | 新版本的扇区可能变少，越界不代表目标不存在 |
| 没有 `fingerprint` 的 `pin` 仍只按下标选中，结果为 `EXACT`，`fingerprintChecked: false`，不加警告 | 不改变已有补丁的行为；回执和 `planPatch` 的 `pins` 如实写出没有校验指纹 |
| `planPatch`、`applyPatch` 的结果增加 `pins`，每个 pin 一条结果；冲突问题带 `candidates`（最多 10 个，按相似度降序）。回执的 `selection` 增加 `RELOCATED`，校验过指纹的选择带 `score`；`EXACT` 的下标必须等于 `expectedIndex`，`RELOCATED` 必须不等 | 报告和工作台需要逐个 pin 的结果。回执是撤销的依据，白名单校验要能拒绝自相矛盾的选择 |
| haunted-house 的 `strobe-start-map01` 补上指纹，取自 Freedoom 0.13.0 MAP01 #0。取代上一节“`pin` 不写 fingerprint” | 指纹校验已经实现 |

### 校准

数据是 Freedoom 0.12.1 和 0.13.0 的 `freedoom2.wad`，两个版本的 32 张地图都有差异，MAP01 从 198 个扇区变成 211 个。把每张地图的每个扇区都当作一个带自身指纹的 pin，在另一个版本上解析，两个方向共 21636 个 pin。对照是独立于指纹的判断：边界线段坐标完全相同、并且在两个版本里都唯一的扇区，共 12996 个 pin 有对照。“同版本歧义”是在 0.13.0 自身上解析时不是 `EXACT` 的 pin（共 10323 个）。

先在几何中心半径 64、还没有“第二名必须低于 0.85”这一条时比较 margin：

| margin | 选错 | 对照一致 |
| ---: | ---: | ---: |
| 0 | 8（其中 7 个是并列第一被选中） | 12797 |
| 0.05 | 1（0.85 对 0.8） | 12703 |
| 0.1 | 0 | 12453 |
| 0.15 | 0 | 12097 |

取 0.1，并加上“第二名必须低于 0.85”和“并列第一一定是歧义”。之后比较几何中心半径：

| 半径 | 选错 | 对照一致 | 无对照但应用 | 同版本歧义 |
| ---: | ---: | ---: | ---: | ---: |
| 16 | 0 | 12453（95.8%） | 725 | 334 |
| 32 | 0 | 12319（94.8%） | 1111 | 426 |
| 64 | 0 | 11909（91.6%） | 1406 | 685 |
| 128 | 1 | 11205（86.2%） | 1646 | 1206 |

取 32。16 的对照一致率最高，但几何中心偏移 8 个单位就到不了 0.85；抽查“无对照但应用”的例子，几何改过的扇区中心常偏移 1 到 8 个单位。32 在没有选错的前提下保留了对这类小改动的容忍。这是判断，不是证明：无对照但应用的 1111 个 pin 是否选对，没有逐个核对。0.85 和 0.5 没有改。

### 真实版本重放

## 2026-11-09：指纹加入边界框和面积

上一版 `docs/relocation-report.md` 写的“有对照的 pin 没有一个被重定位到错误的扇区”只覆盖边界线段完全没变的扇区（对照一）。用面积覆盖核对几何改过的扇区，发现旧指纹会选错，例如 0.12.1 → 0.13.0 的 MAP12 #908 和 #919 都被定位到 #752，MAP05 #107 → #66，MAP12 #1072 → #152，覆盖率都是 0。原因是指纹的几何部分只有几何中心，中心相同、大小不同的同心或互补结构（水面中间的桥、两条竖条夹一条竖条）属性又相同时，旧公式能给到 0.85 以上。

| 决定 | 原因 |
| :--- | :--- |
| 指纹增加 `bbox`（边界线段端点的 [minX, minY, maxX, maxY]）和 `area`（面积，四舍五入到整数），共八个键。缺键或多键仍是 `INVALID_PATCH`，所以旧的六键指纹现在会被拒绝，不做兼容 | 用户确认不需要兼容旧指纹。静默接受旧指纹，就等于对这些 pin 不做大小和形状的核对 |
| 面积用鞋带公式按 Linedef 的方向求：正面 Sidedef 属于该扇区时取负的叉积，背面属于时取正的叉积，再取绝对值。两面都属于同一扇区的线段互相抵消，孔洞自动扣除 | 只加 bbox 时，校准集里仍有 20 个 pin 与别的 pin 共用目标，例如 0.13.0 → 0.12.1 的 MAP01 #106 → #52：两者边界框恰好相同，但 #106 是新划出的水道。面积能区分边界框相同、形状不同的扇区。边界不闭合时它不是真实面积，但仍是确定的数 |
| 边界框按重叠比例打分：每个轴 (重叠 + 8) / (并集 + 8)，两轴相乘；不用“四条边最大偏移按半径衰减” | 同样权重下，重叠比例对窄扇区更严格（8 单位宽的扇区平移 8 单位，重叠为 0），对大扇区的小改动更宽容。见下面的比较 |
| 权重：几何中心 0.2、边界框 0.3、面积 0.2、高度 0.1，线段数、`floorpic`、`ceilingpic`、`tag` 各 0.05。几何中心半径仍为 32，面积按 (较小 + 64) / (较大 + 64) | 几何合计 0.7，属性完全相同、几何完全不同的扇区最多 0.3。在网格里覆盖率 < 0.5 的数量和共用目标的数量都在这一档附近持平，没有选最靠边的点 |
| 阈值 0.85、0.5、0.1 不变 | 这次只校准指纹公式。没有证据表明阈值是问题所在 |
| 校准只用 0.12.1 和 0.13.0；0.11.3 做留出验证，不为它调整任何参数 | 用留出集调参，它就不再能说明公式在没见过的版本上表现如何 |
| 重定位报告加入第二个独立对照“面积覆盖”（`scripts/relocation-controls.ts`），统计覆盖率 < 0.5 的被应用 pin（按 EXACT、RELOCATED 分开）和多个源 pin 共用的目标，并写明每个数字覆盖哪些扇区；人工抽查的判断写在报告脚本里，结果列由脚本重算 | 只看对照一，几何改过的扇区就没有任何检查。面积覆盖是启发式，抽查发现窄扇区平移、拆分、嵌套结构重画都会让它误报，所以不能单独当真值 |
| EXACT 与 RELOCATED 用同一套阈值，不因为下标相同就放宽 | 旧公式下有 EXACT 选错：0.12.1 → 0.13.0 的 MAP01 #17（0.13.0 的同一下标是 1 单位高的细条），0.13.0 → 0.12.1 的 MAP25 #375（0.12.1 的同一下标是 8×8 的另一个扇区）。新公式下两者分别为 `CONFLICT_AMBIGUOUS` 和 `CONFLICT_MISSING`。分级规则本来就不看下标，问题出在相似度上 |
| core 公开导出 `classifyPin` | 校准脚本和报告要用与补丁引擎相同的分级规则重算修复前的公式。它是纯函数，只按相似度分级，不涉及写入 |
| 新增回归测试 `test/relocation-regression.test.ts`：上面四个样例和两个 EXACT 样例。指纹对直接写在测试里（只是算出来的数），不依赖缓存也能断言新相似度低于 0.85、旧公式达到 0.85；有缓存时再在真实地图上断言不会选中错误目标 | 完整发行版不提交，CI 里缓存不存在时真实地图部分会跳过，指纹对部分仍然运行 |
| Freedoom 0.11.3：GitHub 发行版 `freedoom-0.11.3.zip`（18889307 字节，与 GitHub API 列出的大小一致），解压到 `fixtures/cache/freedoom-0.11.3/`，不提交。zip 的 SHA-256 为 `28a5eafbb1285b78937bd408fcdd8f25f915432340eee79da692eae83bce5e8a`，`freedoom2.wad` 为 `d91080adcdaa14f46977887c044a1213bea92d19d73a87be58ec5c354c2d5962` | 这个发行版没有附带校验清单，只有 `.asc` 签名；本机没有 gpg，签名没有验证 |
